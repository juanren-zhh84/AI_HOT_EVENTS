# AI_Hot_Events 未落地功能补齐计划

## Summary
当前项目已具备“仓库采集 - 星标快照 - 热点计算 - 邮件日报”的基础闭环，但与需求文档相比，仍缺少面向 AI/Agent 热门开源项目的自动发现、项目画像生成、订阅管理闭环和更严格的热度筛选规则。本计划优先补齐最影响结果质量的部分，再补运维与交付能力。

## Key Changes
1. 补“监控源管理 + 自动发现”
   - 新增 GitHub Search / Topic / 组织用户源的发现流程。
   - 定义 source 的启用、禁用、优先级、采集频率和过滤条件。
   - 发现到的新仓库自动入库，并打上 `AI` / `Agent` / 相关技术标签。

2. 补“项目画像 + 技术栈识别”
   - 新增 `project_profiles` 生成链路。
   - 基于 `description`、`topics`、`README`、`languages`、依赖文件生成摘要、功能点、适用人群、使用门槛、亮点。
   - 完成技术栈识别结果落库和接口输出。

3. 调整“热点筛选逻辑”
   - 热度计算补齐文档里的硬条件：最低 stars、24h/7d 增长、最近提交时间、仓库状态过滤。
   - 让评分公式与需求文档对齐，保留 `reason` 可解释结果。
   - 增加 AI/Agent 关键词或 topic 维度的候选优先级。

4. 补“邮件日报交付”
   - 日报内容补齐采集窗口、统计窗口、项目画像、技术栈、退订入口。
   - 订阅者支持启用/禁用/退订。
   - 增加发送失败重试与状态记录。

5. 补“管理接口与安全”
   - 管理 API 增加鉴权。
   - 补齐监控源、任务、快照、热点榜、日报、限流状态的查询接口。
   - 输出统一的 OpenAPI 可读接口结构。

## Test Plan
1. 自动发现测试
   - 能从 Search / Topic / 组织源发现候选仓库。
   - 新仓库可正确落库，且可按 AI/Agent 规则命中标签。

2. 热点计算测试
   - 24h / 7d 增量计算正确。
   - archived / disabled / 不活跃仓库被正确过滤。
   - 热度排序与文档公式一致。

3. 项目画像测试
   - README 缺失、过长、格式差时能降级到 description。
   - 技术栈识别可从依赖文件和 languages 正确产出。

4. 邮件日报测试
   - HTML / text 两种格式均能生成。
   - 订阅者状态、退订与重复投递行为正确。
   - 失败可记录原因，重试不会重复生成脏数据。

5. 接口与安全测试
   - 管理接口鉴权生效。
   - 主要查询接口返回字段与 schema 对齐。

## Assumptions
- 先以现有 FastAPI + SQLAlchemy + APScheduler 架构继续扩展，不重做系统。
- AI/Agent 相关项目优先通过 GitHub topic、关键词和 README 语义特征筛选。
- 现阶段优先补齐 MVP 必需闭环，不先做复杂的多租户、队列分片或大模型推理编排。
