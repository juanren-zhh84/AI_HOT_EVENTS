# 后续阶段计划

## Summary

本文档用于承接 `计划.md` 之后的开发阶段。

当前项目已经完成 1-7 步核心业务主链路：

```text
仓库添加
-> GitHub 数据采集
-> star 快照
-> 热点计算
-> 邮件日报
-> SMTP 发送
```

后续重点从“手动可用”进入“自动运行、可测试、可部署”。

## 8. 自动调度服务

目标：把当前手动调用接口的流程升级为后台自动执行。

计划任务：

1. 星标快照采集任务
   - 调用 `StarSnapshotService.run_snapshot()`。
   - 默认 cron：`STAR_SNAPSHOT_CRON=0 * * * *`。
   - 含义：每小时采集一次所有启用仓库的 GitHub 指标。

2. 热点项目计算任务
   - 调用 `HotProjectService.calculate_hot_projects()`。
   - 默认 cron：`HOT_PROJECT_CRON=30 8 * * *`。
   - 含义：每天 08:30 计算当天热点榜。

3. 邮件日报发送任务
   - 调用 `EmailDigestService.run_digest()`。
   - 默认 cron：`DIGEST_CRON=0 9 * * *`。
   - 含义：每天 09:00 给 `active` 订阅者发送日报。

交付物：

- 新增 `app/services/scheduler_service.py`。
- 在 `app/main.py` 的应用启动时启动调度器。
- 在 `app/main.py` 的应用关闭时停止调度器。
- 调度器执行失败时不能导致 FastAPI 服务退出。
- 每个任务执行结果写入日志，方便排查。

验收标准：

- 启动服务后，调度器自动启动。
- 手动等待或临时改 cron 后，能自动触发任务。
- 任务异常时服务仍然可用。
- 不影响现有手动接口。

## 9. 自动化测试补充

目标：把已经验证过的核心流程沉淀成可重复运行的测试脚本。

优先覆盖：

1. 仓库创建接口。
2. 星标快照采集接口。
3. 热点计算接口。
4. 邮件 `dry_run` 接口。
5. 重复正式发送日报不再返回 500 的回归测试。

重点回归测试：

- 同一天、同一份日报、同一个订阅者重复发送时：
  - 不新增重复 `email_deliveries`。
  - 复用旧投递记录。
  - 接口不返回 500。

## 10. 部署准备

目标：让项目可以从本地开发平滑迁移到服务器。

计划内容：

1. 新增 `.env.example`
   - 只放配置名和示例值。
   - 不包含真实 GitHub Token、SMTP 授权码、数据库密码。

2. 整理服务器启动命令
   - 本地开发继续使用 Conda。
   - 服务器部署使用 `.venv`。

3. 编写部署文档
   - Python 环境创建。
   - 依赖安装。
   - `.env` 配置。
   - MySQL 表结构准备。
   - uvicorn 启动方式。
   - 后台运行方式。
